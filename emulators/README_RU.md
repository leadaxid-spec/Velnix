# Velnix Client — отдельный клиентский бот

Клиентская часть v21 из ранее подготовленного пакета. Код Warning в этот архив не включён. Файлы приложения не изменены, главный файл назван client_bot.py.

## Состав

- client_bot.py — Telegram-интерфейс, комнаты, приборы и управление климатом.
- room_emulators/ — встроенные комнатные эмуляторы термостата, вентиляции, кондиционера и увлажнителя.
- client_bridge.py — публикация локального снимка состояний для возможной будущей связки. Запуск Warning для работы Client не нужен.

Настоящие токены, адреса жильцов и файлы доступов Ujin в архив не включены.

## Новый запуск на Mac

Python 3.9.6 подходит. Используется стандартная библиотека, устанавливать пакеты через pip не требуется.

Распакуйте ZIP в «Загрузки». В Терминале выполните:

```bash
cd ~/Downloads/velnix_client_only
python3 -m py_compile client_bot.py client_bridge.py
```

Затем в стандартной оболочке macOS zsh задайте токен именно клиентского бота:

```zsh
read -s "TELEGRAM_BOT_TOKEN?Вставьте токен Client и нажмите Enter: "
export TELEGRAM_BOT_TOKEN
```

Если username вашего бота отличается от velnix_client_bot, укажите его без @. Например, для бота с username my_client_test_bot:

```bash
export TELEGRAM_BOT_USERNAME="my_client_test_bot"
```

Замените пример собственным username. Он нужен для корректных приглашений.

Запустите:

```bash
python3 client_bot.py
```

Откройте своего бота в Telegram и отправьте /start. При первом запуске коды тестового входа появятся в Терминале. Не публикуйте их. Программа должна продолжать работать в этой вкладке. Для остановки нажмите Control+C. После закрытия вкладки переменную токена потребуется задать снова.

## Обновление уже работающего Client

Если вы уже запускали клиентский бот из ~/velnix_bot, не начинайте регистрацию в новой папке: данные сохраняются рядом с программой.

Остановите прежний Client сочетанием Control+C. Сделайте копию всей папки с кодом и сохранёнными данными:

```bash
cp -R ~/velnix_bot ~/velnix_bot_backup_before_client_only
```

Используйте новое имя резервной копии, если такое уже существует. Затем скопируйте только код:

```bash
cp ~/Downloads/velnix_client_only/client_bot.py ~/velnix_bot/client_bot.py
cp ~/Downloads/velnix_client_only/client_bridge.py ~/velnix_bot/client_bridge.py
cp -R ~/Downloads/velnix_client_only/room_emulators ~/velnix_bot/
cd ~/velnix_bot
python3 -m py_compile client_bot.py client_bridge.py
python3 client_bot.py
```

Команды предполагают, что ZIP распакован в ~/Downloads/velnix_client_only. JSON-файлы со своими данными не удаляйте и не заменяйте. Если открыта новая вкладка, сначала задайте токен и username, как описано выше. Один токен должен опрашиваться одним запущенным экземпляром Client.

## Важные границы прототипа

Управление комнатными приборами работает с локальными эмуляторами. Полная интеграция с реальными устройствами Ujin не подтверждена.

В коде также сохранены прежние подключения к отдельным эмуляторам вентиляции на 127.0.0.1:8099 и термостата на 127.0.0.1:8100. Старые программы используют эти подключения. Они не равнозначны программам для произвольных новых комнатных устройств и требуют дальнейшего согласования логики.

Регистрация и доступы предназначены для демонстрации. Подтверждение права на квартиру, полноценные ограничения управляющего и семейные права ещё требуют доработки. Семейная подписка из презентации в этой версии не реализована.

Клиент автоматически публикует снимок локальных приборов в ~/velnix_shared/state.json. Warning для этого не нужен. Снимок содержит местоположение приборов и не предназначен для публичного размещения.

Для первого теста используйте вымышленные адреса и тестовые приборы. Этот пакет — клиентский прототип хакатона, а не готовая эксплуатационная система управления реальным домом.
